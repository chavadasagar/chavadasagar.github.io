# ✍️ Content & Copywriting Guidelines

This document outlines content writing standards, tool naming conventions, meta descriptions, and documentation tone.

---

## 1. Tone & Voice

- **Professional & Clear**: Direct, developer-friendly phrasing.
- **Privacy Emphasized**: Highlight that data remains 100% private and browser-based where applicable.
- **Action-Oriented**: Focus on immediate benefits (e.g. "Convert CSV to JSON instantly", "Compress PNGs without server uploads").

---

## 2. Naming Conventions

- **Page Title (`<title>`)**: `[Tool Name] | Vyunix Tools` or `[Tool Name] — [Subtitle] | Vyunix`
- **Sub-project Folder Name**: Lowercase kebab-case (e.g., `qr-code-generator`, `password-generator`).
- **Main Heading (`<h1>`)**: Clean title matching the folder or tool function.

---

## 3. Sub-Project Documentation (`README.md`)

Every sub-project `README.md` must follow `templates/README.template.md` and contain:

1. **Title & Short Summary**
2. **🚀 Key Features** (Bullet points detailing main functionality)
3. **🛠️ Technology Stack** (HTML5, CSS3, Vanilla JS, Web APIs used)
4. **💻 How to Run Locally**
5. **📁 File Structure**
6. **📱 Browser Compatibility**
