Plans aur Features

Plan ka naam code me kabhi hardcode mat karo (if plan == "pro"). Limits DB me rakho, taaki naya plan bina code change ke add ho sake.

Teen tables

  • plans: naam, price, trial days
  • features: kya cheez limit hoti hai (notes, storage_mb, ai_summaries, team_members)
  • plan_features: kis plan me kis feature ki kitni limit, aur limit hard hai ya soft
SQL Example
CREATE TABLE plan_features (
  id          INT PRIMARY KEY AUTO_INCREMENT,
  plan_id     INT NOT NULL,
  feature_id  INT NOT NULL,
  limit_value INT NOT NULL,          -- -1 = unlimited
  limit_type  ENUM('hard','soft') NOT NULL,
  UNIQUE KEY (plan_id, feature_id)
);

-- Pro plan ki saari limits
SELECT f.code, pf.limit_value, pf.limit_type
FROM plan_features pf
JOIN features f ON f.id = pf.feature_id
WHERE pf.plan_id = 2;

JavaScript Example
// Allowed transitions — galat change ko rokta hai
const TRANSITIONS = {
  trialing: ['active', 'canceled'],
  active:   ['active', 'past_due', 'canceled'],
  past_due: ['active', 'canceled'],
  canceled: []
};

function changeStatus(sub, next) {
  if (!TRANSITIONS[sub.status].includes(next)) {
    throw new Error(`Invalid: ${sub.status} → ${next}`);
  }
  sub.status = next;
}

Signup aur Trial

Signup hote hi user ko Free subscription do aur har feature ka usage counter 0 se banao. Paid plan choose karne par 7 din ka trial start hota hai.

Node.js Example
async function startTrial(userId, planId) {
  const plan = await db.plans.find(planId);
  const now = new Date();
  const trialEnd = addDays(now, plan.trial_days);   // 7

  await db.subscriptions.update(
    { user_id: userId, status: 'active' },
    { status: 'canceled', canceled_at: now }
  );

  return db.subscriptions.insert({
    user_id: userId,
    plan_id: planId,
    status: 'trialing',
    trial_end: trialEnd,
    current_period_start: now,
    current_period_end: trialEnd
  });
}
Dhyan doEk user ko ek hi baar trial do. Check karo ki subscription_events me pehle se trial_started to nahi hai.

Entitlements (Limit Check)

Ek central function can(user, feature, qty) banao. Har protected route isi ko call kare.

Node.js Example
async function can(sub, featureCode, qty = 1) {
  if (['canceled', 'expired'].includes(sub.status))
    return { ok: false, reason: 'Subscription inactive' };

  const pf = await getPlanFeature(sub.plan_id, featureCode);
  if (pf.limit_value === -1) return { ok: true };

  const used = await getUsed(sub.id, featureCode, sub.current_period_start);
  if (used + qty <= pf.limit_value) return { ok: true };

  if (pf.limit_type === 'soft') return { ok: true, overage: true };
  return { ok: false, reason: `Limit reached (${pf.limit_value})` };
}

// Express middleware
const requireQuota = (feature) => async (req, res, next) => {
  const r = await can(req.subscription, feature);
  if (!r.ok) return res.status(402).json({ error: r.reason });
  req.overage = !!r.overage;
  next();
};

app.post('/notes', requireQuota('notes'), createNote);

Payments aur Webhooks

Payment ka result gateway webhook se aata hai. Frontend ka "payment success" message kabhi trust mat karo.

Node.js Example
app.post('/webhooks/payment', async (req, res) => {
  if (!verifySignature(req)) return res.sendStatus(401);
  const evt = req.body;

  try {
    await db.webhook_events.insert({        // event_id UNIQUE
      event_id: evt.id, event_type: evt.type, payload: evt
    });
  } catch (e) {
    if (e.code === 'ER_DUP_ENTRY') return res.sendStatus(200);
    throw e;
  }

  if (evt.type === 'payment.success') await markPaid(evt);
  if (evt.type === 'payment.failed')  await markPastDue(evt);

  await db.webhook_events.update({ event_id: evt.id },
    { status: 'processed', processed_at: new Date() });
  res.sendStatus(200);
});

Invoices aur Overage

Invoice = base price + pichhle period ka overage + 18% GST. Har line invoice_items me alag row hoti hai.

Formula
overage_qty    = max(0, used - limit)        // sirf soft features
overage_amount = overage_qty × overage_unit_price
subtotal       = base + Σ overage_amount
tax            = subtotal × 0.18
total          = subtotal + tax

3. Rahul (Free) 3 naye notes banana chahta hai. Allowed hai?

Nahi. Used 48 + 3 = 51 > 50, aur Free plan me notes ki limit hard hai. Response: 402. Sirf 2 notes ban sakte hain.

4. Karan ka grace 13 Oct ko khatam hua. Kya steps honge?
  • subscriptions.status = canceled, canceled_at = now
  • Invoice INV-2026-0005 ka status = uncollectible
  • Naya Free subscription create
  • subscription_events: canceled, notifications: canceled
  • Notes 780 hain, Free limit 50: data delete nahi, naye notes block
5. Same webhook do baar aaya. Kya hoga?

webhook_events.event_id UNIQUE hai, isliye dusra insert duplicate error dega. Handler 200 return karke skip kar dega, payment do baar record nahi hogi.
